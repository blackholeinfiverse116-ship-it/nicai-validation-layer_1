# Runtime Logs Guide

# Purpose

Runtime logs provide traceability, debugging capability, replay support, and operational auditing.

---

# Log Files

validation_logs.json

Stores validation results.

Includes:

- signal_id
- trace_id
- confidence
- validation status

---

anomaly_logs.json

Stores intelligence outputs.

Includes:

- risk level
- anomaly type
- explanation
- recommendation

---

pattern_logs.json

Stores aggregated pattern information.

Includes:

- cluster summary
- affected regions
- pattern statistics

---

contract_logs.json

Stores contract validation results.

Verifies response schema compatibility.

---

action_logs.json

Stores action recommendations generated by NICAI.

No external actions are executed.

---

tantra_logs.json

Stores participation events for TANTRA integration.

---

ttg_logs.json

Stores TTG participation records.

---

# Replay Dependency

Replay reconstruction depends on these runtime logs.

Deleting logs may reduce replay completeness.

---

# Operational Usage

Logs support:

- Debugging
- Replay
- Trace continuity
- Runtime validation
- Audit evidence

---

# Best Practices

- Preserve logs during testing.
- Archive logs before cleanup.
- Avoid manual modification.
- Use replay for historical analysis.
